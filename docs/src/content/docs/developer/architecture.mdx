---
title: Architecture
description: How profile detection and switching work under the hood.
---

```
Stream Deck starts
       │
       ▼
Plugin connects via WebSocket
       │
       ├─ Loads app-map rules from global settings
       ├─ Tracks all connected Stream Deck devices
       ├─ Mirrors built-in Smart Profile targets (AppIdentifier)
       └─ Polls every 150 ms (persistent PowerShell → Win32)
              │
              ▼
       GetForegroundWindow → process name + window title
              │
              ▼
       Match rules (title-specific → process-only → built-in map)
              │
              ▼
       Resolve targets for each connected device
              │
              ├─ Match  → switchToProfile(device, "ProfileName")
              └─ No match → switchToProfile(device, "")  (release to built-in)
```

## Stability

A process must appear in **two consecutive polls** (~300 ms) before switching. This avoids false triggers during rapid alt-tab.

## Plugin-owned profiles

`switchToProfile` only works when the target manifest includes `InstalledByPluginUUID` for this plugin. The plugin migrates `AppIdentifier` to `PluginSavedAppIdentifier` to avoid conflicts with Smart Profiles.

## Stack depth

Each plugin switch pushes onto Stream Deck's internal stack. `switchToProfile("")` pops one level — the plugin tracks depth and may call it multiple times when peeling back through several plugin-owned profiles.

## Multiple Stream Decks

Rules can use a fallback profile for all devices and optional profile overrides
for individual devices. The plugin maintains `lastProfile` and stack depth per
device, including the initial release and 50 ms delay, so one device's profile
history cannot affect another's. Built-in Smart Profile fallback uses the same
profile name for every connected device.

Profile manifests are machine-global and indexed by name. Use distinct names
for profiles assigned to different devices.
