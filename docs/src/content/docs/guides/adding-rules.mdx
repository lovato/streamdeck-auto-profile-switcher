title: Adding rules
description: Configure app-map rules from test detection or manually.

## From test detection (easiest)

1. Open the property inspector for Auto Profile Switcher.
2. Click **Test detection** and focus the target app within 3 seconds.
3. Click **+ Add this to App List** — process name and title are pre-filled.
4. Choose a fallback profile for all devices, or choose a profile for each connected Stream Deck.
5. Save settings.

## Manual entry

Each rule has:

| Field | Meaning |
| --- | --- |
| **Match** | Process name substring (e.g. `calc`, `windowsterminal`) |
| **Title match** | Optional window title substring |
| **All other devices** | Optional fallback profile for every connected Stream Deck |
| **Device name** | Optional profile override for that specific connected Stream Deck |

Leave **Title match** empty for a process-only rule. A device-specific override
takes precedence over **All other devices**. A rule that only has device
assignments releases the plugin override on connected devices without an
assignment.

Device assignments are saved by Stream Deck device ID. Assignments for a
disconnected device remain visible and are applied when it reconnects. Built-in
Smart Profile matches use the same profile name on every connected device.

Profiles are discovered globally from Stream Deck's `ProfilesV3` directory.
Use distinct names for profiles intended for different devices, such as `Key
Editor (XL)` and `Key Editor (XL+)`.

## Finding process names

**Test detection** is the recommended tool. For apps without a visible window:

```powershell
Get-Process |
  Where-Object { $_.MainWindowTitle -ne "" } |
  Select-Object Name, MainWindowTitle |
  Sort-Object Name
```

## Rule ordering

Put **title-specific** rules above **process-only** fallbacks in the list. The plugin evaluates title rules first.
